# 樱花风散、落樱与临时落瓣

樱花主题使用一个 Canvas 和一套粉白花瓣：平时少量飘动；切页时按目的地换一种转场，再逐片渐隐，最后恢复平时的数量。原首页布局、海滨主题、文章和目录不变。

- **风散**（切换栏目，如博客、读书、项目）：一阵风从页面一侧吹过，像吹散一棵看不见的樱花树，花瓣成簇脱离、在页面上散开再缓缓落下。风向跟随导航顺序：往右边的栏目走，风从左吹来；往回走，风从右吹来；无法判断（同栏目、导航外页面）时随机
- **落樱**（进入文章 `/blog/<slug>`，系列页除外）：没有横扫的风，像一道松散的花帘从导航栏下沿一起落下，穿过整个首屏，边落边散开、渐隐，只带一点随机方向的轻微斜飘。方向一致的整体下落让它一眼能认出是转场，节奏仍然是慢的

## 一段完整的转场

- 桌面常驻池14片，切页临时增加最多28片；手机6＋12，省流量4＋6。实际可见数量还受屏幕边界与阅读保护影响
- 每次都有随机性：风散的临时数量在上限的约75%–100%之间（落樱约85%–100%），出发高度、风力（±15%）、卷曲幅度、每簇片数（3–5片）、簇间隔、落樱的下落速度、花帘的倾斜与斜飘方向都重新抽取，所以相邻两次不会完全一样
- 常驻与风散花瓣绘制尺寸是8–18px；落樱偏近景，约13–20px。浅白、樱粉渐变。翻转保留至少55%厚度，避免变成细碎亮点
- 顶部导航栏固定在画布之上，两种转场都从导航栏下沿开始计算出发位置，旧页停留的340ms里花瓣就已经露出来，不会藏在导航栏后面
- 点击后约0.22秒，原有花瓣先共同向风向轻偏约24px、略抬6px并倾斜约10°，随后平缓松开；落樱时这一偏移只有约三分之一。这是同一风相位上的短小摆动，不是加快整屏横扫或增加粒子数量
- 风散的簇心位于上风一侧的页面边缘、导航栏以下可用高度的约12%–32%处，象征树冠；各簇间隔约0.04–0.09秒先后被风带走。花瓣的风速不是瞬间抛出再急刹，而是约0.4秒缓缓鼓起、再用约1.6秒慢慢松开，交还给日常风场继续翻飞、下落；途中带一点上下卷曲，同簇花瓣速度各不相同，自然拉开
- 落樱约四分之三的花瓣在点击瞬间排在导航栏下方约12%高度内，横向铺满，一起以每秒约17%–21%可用高度的速度下落（桌面上限190px/秒），每片快慢相差约±8%，帘子随之慢慢松开；其余四分之一在0.3–0.9秒后从导航栏后面跟着飘下。标题区里落樱比风散更清楚一些（透明度下限0.88，风散0.62），因为它只是短暂经过标题
- 每片新增花瓣寿命：风散约3.1–4.0秒，落樱约4.1–4.5秒。先用约0.45秒淡入；风散寿命过35%、落樱过50%后，用余下的时间缓慢淡出，淡出时略微缩小（最多18%），不在统一时间突然删除；过期后从临时池移除，下一次入场替换临时池而不累加
- 手机只在页头范围内绘制临时花瓣，所以手机上两种转场的出发位置都限定在页头的可见高度内
- 独立 SVG 转场层不再绘制，避免两层叠加造成密度过高、动作互相掩盖
- 普通站内跨页链接在旧页立即起风，最多保留340ms让花瓣先出现，再由浏览器原生加载新文档。连续改点目的地不重置这段时间；已在加载时更新目标会立即交给浏览器。外链、修饰键、下载、其他target与锚点保持原生行为；同页顶部导航只回到页首，不刷新或重播。没有客户端路由、DOM替换或额外history记录
- Canvas 完成后通知入场状态清理，4500ms兜底不阻塞导航。暂停或系统减少动态效果优先，可立即终止整段动效
- 同一段导航脚本也服务海蓝诗境的潮汐转场：海蓝诗境下改派发 `coastal-navigation-*` 事件，并以 `coastalReady` 与 `poetizeMotion` 判断能否停留。停留期间切换主题会取消原主题的这次转场，不会把樱花的停留交给海浪，反之亦然。见 [视觉主题 · 潮汐转场](visual-themes.md#潮汐转场)

旧页将花瓣坐标、风速、卷曲、相位、剩余寿命、转场样式与风向和同一episode标识保存在短时sessionStorage中；真正pagehide时再保存最后可见状态，目标页只消费与自身URL匹配的记录并续接，避免慢加载倒带或重播。记录10秒过期，存储不可用/脚本未就绪时链接立即回退到原生导航。Escape及同页取消会停止尚在加载的目标，并清除临时状态。仅在接续回首页时跳过原本从全透明开始的欢迎标题动画，避免风已经接续、标题却重新消失；首次直接打开首页仍保留原入场。

右下角「风起」继续驱动同一画布；日常周期微风与鼠标轻风保留。同视口历史恢复不会重新散布常驻花瓣，新一次入场的临时池有固定上限。

## 阅读、偏好与性能

正文与目录安全区域不绘制花瓣。窄文章隐藏控件时，同时停帧并清空全部花瓣；手机离开首屏或进入正文停止画布。回到有空间的区域时按保存的偏好恢复。临时花瓣经过短页标题后可继续渐隐，不会仅因跨过标题边界被突然切掉；接近受保护的正文或手机首屏边界时提前淡去。

暂停偏好沿用 sakura-effects，存储不可用时仍可控制当前页。减少动态效果、海滨主题、工作台、编辑器、项目文档不启用本动效。页面隐藏时停帧并取消临时花瓣。

仍使用预绘制花瓣图块和一个有界动画循环。桌面最多60fps，手机/省流量最多30fps；DPR上限1.5/1.25，总位图上限约300万像素。没有新运行依赖、树插画或大粒子遮罩。

## 验证

```sh
npm run verify
npm run preview -- --host 127.0.0.1 --port 4323
PLAYWRIGHT_MODULE=/path/to/playwright/index.mjs PREVIEW_URL=http://127.0.0.1:4323 node scripts/verify-sakura-motion.mjs
```

渲染函数的生命周期测试验证基线→临时增量→透明度降低→恢复基线，风散沿导航顺序的方向、进入文章时的落樱（旧页停留期内可见、明显下落、跨页续接）、两种转场都从导航栏下方开始、每次转场的随机差异，以及重复输入、暂停、减少动态效果、阅读保护与省流量。浏览器脚本采样实际 Canvas 的绘制数量与透明度，保存 breeze-lifecycle-timeline.json，并检查导航、历史、正文、开关、手机和海滨隔离。

Canvas 的 data-sakura-base-pool、data-sakura-base-count、data-sakura-burst-count、data-sakura-burst-pool、data-sakura-burst-state、data-sakura-style、data-sakura-wind-from 只用于可重复地观察渲染状态；这些计数不代替连续画面的观感检查。模拟测试与桌面浏览器检查均不能当作实体手机或个人视觉舒适度保证。
